01 Executive Verdict & Core Concept تعریف و چشم‌انداز بنیادین (Executive Verdict)

RemoteCompose is Android's next-generation declarative remote UI framework designed in the Android Open Source Project (AOSP) and Jetpack Compose. It enables applications or cloud backends to serialize an entire interactive Compose UI tree and vector drawing pipeline into a compact, high-efficiency binary bytecode stream (.rc wire format) that is rendered, animated, and interacted with on another device, display, or sandboxed process without transferring executable code. RemoteCompose نسل نوین فریم‌ورک رابط کاربری راه دور (Remote UI) در پروژه متن‌باز اندروید (AOSP) و Jetpack Compose است. این فناوری به برنامه‌ها و سرورهای ابری اجازه می‌دهد که یک درخت رابط کاربری تعاملی کامپوز و خط لوله ترسیم برداری را درون یک رشته بایت فشرده باینری (فرمت بایت‌کد .rc) سریال‌سازی کرده و آن را در دستگاه، نمایشگر یا پروسه ایزوله دیگر بدون نیاز به انتقال کدهای اجرایی رندر، متحرک‌سازی و مدیریت کنند.
⚡

Binary Wire Format پروتکل باینری فوق فشرده

Replaces bulky JSON, XML layouts, and Parcelable IPC envelopes with an OpCode-driven flat byte buffer (WireBuffer), slashing cross-process and network payloads by 85–90%. با جایگزینی ساختارهای سنگین JSON، کدهای XML و بسته‌های حجیم Parcelable با یک بافر مسطح از کدهای عملیاتی (WireBuffer)، حجم داده‌های بین‌پراسی و شبکه را تا ۸۵ الی ۹۰ درصد کاهش می‌دهد.

🧮

Embedded RPN Engine موتور ریاضی و محاسبات محلی RPN

Contains an embedded Reverse Polish Notation (RPN) mathematical virtual machine that evaluates dynamic expressions, physics springs, and gestures at 60/120 FPS locally on the Player hardware. مجهز به یک ماشین مجازی مبتنی بر نمادگذاری معکوس لهستانی (RPN) است که محاسبات متغیرها، انیمیشن‌های فیزیکی و بازخورد لمسی را با نرخ ۶۰ و ۱۲۰ فریم بر ثانیه مستقیماً در سخت‌افزار پخش‌کننده اجرا می‌کند.

🛡️

Hermetic Sandbox ایزولاسیون و امنیت سخت‌گیرانه

Zero arbitrary bytecode (DEX/JVM) execution. Host processes play back deterministic vector commands without vulnerability to memory corruption, infinite loops, or malicious code injection. فاقد اجرای بایت‌کدهای اجرایی متفرقه (DEX یا JVM). سیستم میزبان تنها دستورات جبری و هندسی مشخص را ترسیم می‌کند که خطرات نشت حافظه، حلقه‌های بی‌پایان و نفوذ امنیتی را به صفر می‌رساند.

ℹ️ The Problem RemoteCompose Solves ریشه پیدایش و مشکلی که حل می‌کند

For over 15 years, Android relied on RemoteViews for cross-process UI (Widgets, Notifications, Auto). RemoteViews works via heavy Java reflection across Binder IPC, supports only a tiny whitelist of primitive views (like LinearLayout and TextView), forbids custom Canvas drawing, and cannot run fluid animations without sending full hierarchy rebuilds over IPC on every frame. RemoteCompose fixes this permanently by decoupling UI declaration from UI execution. برای بیش از ۱۵ سال، سیستم‌عامل Android برای نمایش رابط کاربری میان پروسه‌ها (ویجت‌ها، اعلان‌ها و داشبورد خودرو) بر پایه RemoteViews کار می‌کرد. RemoteViews از ریفلکشن سنگین جاوا روی Binder IPC استفاده می‌کرد، تنها فهرست محدودی از نماهای ساده را می‌پذیرفت، اجازه ترسیم آزاد Canvas را نمی‌داد و برای کوچک‌ترین انیمیشن مجبور به ارسال مجدد کل ساختار ویجت بود. RemoteCompose با تفکیک ساختاری اعلام رابط کاربری از اجرای رندرینگ این گلوگاه قدیمی را رفع کرده است.

02 System Architecture & Pipeline معماری سیستم و خط لوله پردازش داده

The RemoteCompose ecosystem in androidx.compose.remote is partitioned into three decoupled functional layers: the Creation Tier (Producer), the Binary Wire Protocol (Data Buffer), and the Player Tier (Consumer). اکوسیستم RemoteCompose در پکیج androidx.compose.remote به سه لایه کاملاً مستقل تفکیک شده است: لایه ساخت (تولیدکننده)، پروتکل باینری سیم‌کشی (Wire Protocol) و لایه پخش‌کننده (مصرف‌کننده).

1. Creation Layer (`remote-creation`) ۱. لایه ساخت (`remote-creation`)

Developers write standard declarative Compose using @RemoteComposable functions or procedural RemoteComposeWriter. Instead of producing Android Views or Compose layout nodes directly on screen, layout modifiers and canvas draws emit serialized command primitives into a WireBuffer. توسعه‌دهندگان کدهای خود را با توابع @RemoteComposable یا کلاس RemoteComposeWriter می‌نویسند. به جای ایجاد مستقیم نماها روی صفحه، تمام مادیفایرها و ترسیمات گرافیکی به شکل کدهای عملیاتی درون یک شیء WireBuffer ذخیره می‌شوند.

2. Player Layer (`remote-player`) ۲. لایه پخش‌کننده (`remote-player`)

The host environment embeds RemoteComposePlayer (a hardware-accelerated Android View FrameLayout) or remote-player-compose. It decodes operations into a CoreDocument, measures components, and paints directly to Skia / Android Canvas. محیط میزبان از کامپوننت RemoteComposePlayer (یک فریم‌لی‌آوت شتاب‌یافته سخت‌افزاری) یا ماژول remote-player-compose استفاده می‌کند. این لایه بایت‌ها را در CoreDocument واکشی کرده و مستقیماً روی بوم Skia یا Android Canvas رندر می‌کند.

03 Under the Hood: What Happens in the Background? موتور داخلی: پردازش در پس‌زمینه چگونه کار می‌کند؟

When a RemoteCompose document is transferred across process boundaries or downloaded from a cloud endpoint, the background runtime performs a rigorous multi-stage pipeline: هنگامی که یک سند RemoteCompose میان دو پروسه منتقل شده یا از سرور ابری دانلود می‌شود، موتور پس‌زمینه مراحل چندگانه و دقیقی را به ترتیب زیر طی می‌کند:

1️⃣

Header Parsing & Capability Negotiation تحلیل هدر و سنجش سازگاری

The player reads OpCode 0 (HEADER), inspecting major/minor protocol versions, canvas dimensions, screen density, scroll capabilities, and the COMPRESS flag. If compressed, the remaining stream is decompressed via fast in-memory Deflate. پخش‌کننده ابتدا دستور هدر (OpCode 0) را خوانده و نگارش پروتکل، ابعاد طراحی، تراکم پیکسلی، وضعیت اسکرول و فلگ فشرده‌سازی را بررسی می‌کند. در صورت فشرده بودن، ادامه بافر با الگوریتم سریع Deflate در حافظه RAM بازگشایی می‌شود.

2️⃣

ID Mapping & Resource Interning نگاشت شناسه‌ها و مدیریت منابع

Strings, vector paths, font faces, shaders, and bitmap textures are indexed by unique integer IDs. This guarantees that duplicate text runs or complex path geometries are encoded only once in the payload table and referenced by ID. رشته‌های متنی، مسیرهای برداری (Paths)، شیدرها و تصاویر بیت‌مپ با شناسه‌های عددی یکتا فهرست‌بندی می‌شوند. بدین ترتیب متن‌های تکراری یا بردارها تنها یک‌بار در جدول بافر نوشته شده و در بقیه نقاط با شناسه سبک ارجاع داده می‌شوند.

3️⃣

Layout Tree & Constraint Resolution ساخت درخت چیدمان و اندازه‌گیری ابعاد

Unlike primitive display lists, RemoteCompose constructs a dynamic layout hierarchy (BoxLayout, RowLayout, ColumnLayout). It executes measure passes to resolve wrap-content, match-parent, padding, and offset constraints adaptively to the host window size. برخلاف فهرست‌های ساده ترسیم، RemoteCompose یک درخت چیدمان پویا تشکیل می‌دهد و اندازه کامپوننت‌ها را با توجه به حاشیه‌ها (Padding)، آفست و اندازه پنجره دستگاه مقصد به صورت تطبیقی اندازه می‌گیرد.

4️⃣

Continuous Paint Context Execution اجرای مداوم ترسیم روی بوم گرافیکی

At render time, RemoteContext feeds transformed matrices, clipping paths, shaders, and draw calls into PaintContext. Dynamic expressions modify parameters in place each frame without invalidating or re-allocating layout trees. در زمان رندر، RemoteContext ماتریس‌های تبدیل، مسیرهای برش، شیدرها و دستورات نقاشی را به PaintContext می‌سپارد. متغیرهای پویا بدون نیاز به بازسازی کل ساختار، پارامترهای هر فریم را درجا به‌روزرسانی می‌کنند.

04 RPN Math & Reactivity Engine موتور عبارات RPN و انیمیشن محلی بدون تأخیر

The single most revolutionary architectural feature of RemoteCompose is its embedded RPN (Reverse Polish Notation) Expression Engine. In traditional Remote UI (such as RemoteViews or JSON-driven frameworks), if an element needs to move, rotate, or respond to time, the host has to re-serialize and transmit a new snapshot over IPC or the network. انقلابی‌ترین نوآوری معماری در RemoteCompose، وجود موتور عبارات محاسباتی مبتنی بر نمادگذاری معکوس لهستانی (RPN) است. در رویکردهای سنتی، هر گونه حرکت یا چرخش یا واکنش به گذر زمان نیازمند محاسبه مجدد در مبدا و ارسال یک فریم یا بسته جدید از طریق IPC یا شبکه بود.

How RPN Stack Evaluation Works عملکرد پشته ارزیابی RPN

Expressions are encoded as an array of float IDs, constants, and math opcodes. For instance, the expression (TouchX + 50) * 1.5 is serialized as:

[VAR_TOUCH_X, 50.0, OP_ADD, 1.5, OP_MUL]

The Player's stack machine pops operands, applies operators in hardware CPU registers, and pushes intermediate results back without allocating heap memory. عبارات ریاضی به شکل آرایه‌ای فشرده از شناسه‌های متغیر، مقادیر ثابت و کدهای عملیاتی ذخیره می‌شوند. برای نمونه عبارت (TouchX + 50) * 1.5 به شکل زیر در می‌آید:

[VAR_TOUCH_X, 50.0, OP_ADD, 1.5, OP_MUL]

ماشین پشته در سمت پخش‌کننده، عملوندها را با سرعت فوق‌العاده بالا و بدون درگیر ساختن حافظه Heap یا زباله‌روب محاسبه می‌کند.

Live System Variables متغیرهای زنده متصل به سخت‌افزار

RemoteCompose binds local hardware events directly to variables monitored by expressions:

  • TimeVariables.SYSTEM_TIME: Real-time wall clock milliseconds
  • TimeVariables.ANIMATION_TIME: High-precision monotonic frame delta
  • TouchVariables.TOUCH_X / Y: Real-time gesture coordinates
  • SensorVariables.ACCELEROMETER: Physical tilt and motion vectors
متغیرهای سیستمی و سخت‌افزاری مستقیماً بدون نیاز به تبادل پیام با مبدا، در متغیرهای سند به‌روزرسانی می‌شوند:
  • TimeVariables.SYSTEM_TIME: میلی‌ثانیه‌های ساعت رسمی سیستم
  • TimeVariables.ANIMATION_TIME: زمان دقیق مونوکوتیک فریم انیمیشن
  • TouchVariables.TOUCH_X / Y: موقعیت لحظه‌ای اشاره‌گر لمسی
  • SensorVariables.ACCELEROMETER: شتاب‌سنج و حسگر زاویه فیزیکی

Java AnimatedFloatExpression.java — AOSP Evaluation Core 
// Inside AOSP com.android.internal.widget.remotecompose.core.operations.utilities
public float eval(RemoteContext context) {
    float[] stack = mStack;
    int sp = 0;
    for (int i = 0; i < mOps.length; i++) {
        float op = mOps[i];
        if (op >= 0 || !isOpcode(op)) {
            stack[sp++] = resolveValue(op, context);
        } else {
            int code = (int) -op;
            switch (code) {
                case OP_ADD:  stack[sp - 2] += stack[sp - 1]; sp--; break;
                case OP_SUB:  stack[sp - 2] -= stack[sp - 1]; sp--; break;
                case OP_MUL:  stack[sp - 2] *= stack[sp - 1]; sp--; break;
                case OP_DIV:  stack[sp - 2] /= stack[sp - 1]; sp--; break;
                case OP_SIN:  stack[sp - 1] = (float) Math.sin(stack[sp - 1]); break;
                case OP_COS:  stack[sp - 1] = (float) Math.cos(stack[sp - 1]); break;
                case OP_IFELSE:
                    float cond = stack[sp - 3];
                    stack[sp - 3] = (cond > 0) ? stack[sp - 2] : stack[sp - 1];
                    sp -= 2;
                    break;
            }
        }
    }
    return stack[0];
}

06 Real-World Industrial Use Cases کاربردهای عملی در صنعت و سیستم‌عامل

RemoteCompose is engineered to power high-scale, cross-device Android applications where native rendering performance, battery longevity, and security boundaries are paramount: فناوری RemoteCompose برای سناریوهایی طراحی شده که ترکیب سرعت فوق‌العاده رندرینگ نیتیو، بهینه‌سازی حداکثری باتری و مرزبندی‌های امنیتی اهمیت حیاتی دارند:

📱

1. Next-Gen AppWidgets & Lockscreen (SystemUI) ۱. نسل نوین ویجت‌ها و صفحه قفل اندروید (SystemUI)

Traditional AppWidgets freeze during heavy CPU loads because updating them requires starting background application processes. With RemoteCompose, the widget's UI is shipped once as a dynamic binary document; SystemUI plays back clock ticking, weather gauge swings, and fluid charts locally with zero battery drain. ویجت‌های قدیمی اندروید به دلیل نیاز به راه‌اندازی مکرر پروسه اپلیکیشن در پس‌زمینه، با لگ مواجه می‌شدند. با RemoteCompose سند ویجت تنها یک‌بار ارسال شده و انیمیشن‌های ساعت، نمودارهای زنده و انیمیشن‌های سیال توسط پروسه SystemUI بدون بیدار کردن برنامه اجرا می‌شوند.

⌚

2. Wear OS / Smartwatches (`wear/compose/remote`) ۲. ساعت‌های هوشمند Wear OS با مصرف میکرو-واتی

Running a full Android JVM and Jetpack Compose measure/layout pass on a tiny smartwatch burns battery rapidly. RemoteCompose offloads UI authoring to a paired smartphone or background service: the watch receives a pre-compiled .rc file and executes time and heart-rate animations directly in the display controller. اجرای ماشین مجازی و چیدمان کامپوز روی پردازنده کوچک ساعت هوشمند باتری را سریعاً خالی می‌کند. با RemoteCompose، موبایل یا سرویس پس‌زمینه سند را می‌سازد و ساعت بدون نیاز به پردازش سنگین کاتلین، داده‌های ضربان قلب و زمان را با حداقل مصرف انرژی نمایش می‌دهد.

🚗

3. Android Automotive OS (AAOS) & Cluster Projection ۳. خودروهای هوشمند (AAOS) و پروژکشن پشت‌آمپر

Displaying navigation arrows, media widgets, or ADAS indicators across isolated instrument clusters requires strict process sandboxing. RemoteCompose streams UI instructions across safety boundaries without risking vehicle gauge crashes. پروژکشن ویجت‌های مسیریابی و مالتی‌مدیا به صفحه کیلومترشمار دیجیتال یا هدآپ دیسپلی خودرو نیازمند ایزولاسیون صددرصدی است. RemoteCompose دستورات رابط کاربری را بدون کوچک‌ترین ریسک کرش کردن پروسه اصلی خودرو منتقل می‌کند.

☁️

4. Server-Driven UI (SDUI) & Cloud Instant Feeds ۴. رابط کاربری سمت سرور (SDUI) بدون نیاز به آپدیت استور

E-commerce, banking, and media apps can stream rich native Compose layouts directly from Go or Kotlin backend servers.
